# Atlas Repository Scanning Contract v0.1

## Status

Approved for Milestone 2

---

# Purpose

Define the Milestone 2 `Scan` entity shape and backend API contract required to support repository scan creation, list project scans, and get individual scan status.

This document is limited to Milestone 2 scope and should be used by the Developer Agent as the implementation contract for scanning features.

---

# Scope

This contract covers:

* `Scan` entity definition
* Database table schema for `scans`
* Repository scanning API endpoints
* Request and response shapes

This contract does not cover:

* File, directory, or dependency database entities (Milestone 3+)
* Knowledge summaries or analysis logic (Milestone 4+)
* Authentication or authorization

---

# Scan Entity

Milestone 2 introduces the persistent entity: `Scan`.

## Fields

### id

* Type: string
* Required: yes
* Description: unique scan identifier generated by Atlas (prefixed with `scan_`)

### projectId

* Type: string
* Required: yes
* Description: associated project identifier

### status

* Type: string (enum: `Pending`, `Running`, `Completed`, `Failed`)
* Required: yes
* Description: current state of the repository scan execution

### createdAt

* Type: string (ISO 8601 datetime with timezone)
* Required: yes
* Description: timestamp indicating when the scan was requested

### startedAt

* Type: string (ISO 8601 datetime with timezone) or null
* Required: no
* Description: timestamp indicating when the scan began execution

### completedAt

* Type: string (ISO 8601 datetime with timezone) or null
* Required: no
* Description: timestamp indicating when the scan finished (successfully or with failure)

### failureReason

* Type: string or null
* Required: no
* Description: detailed failure message if the status is `Failed`

---

# Database Schema

Milestone 2 requires the creation of the `scans` table.

```sql
CREATE TABLE IF NOT EXISTS scans (
    id TEXT PRIMARY KEY,
    project_id TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    status TEXT NOT NULL,
    created_at TIMESTAMPTZ NOT NULL,
    started_at TIMESTAMPTZ,
    completed_at TIMESTAMPTZ,
    failure_reason TEXT
);

CREATE INDEX IF NOT EXISTS idx_scans_project_id ON scans(project_id);
```

# API Style

Milestone 2 uses a simple JSON HTTP API exposed by the backend.

Content type:

* `application/json`

# Endpoints

## Create Scan

### Request

* Method: `POST`
* Path: `/api/projects/{projectId}/scans`
* Request body: empty

### Success Response

* Status: `201 Created`

Response body:

```json
{
  "id": "scan_456a789b",
  "projectId": "project_123",
  "status": "Pending",
  "createdAt": "2026-06-22T10:00:00Z",
  "startedAt": null,
  "completedAt": null,
  "failureReason": null
}
```

### Error Response

* Status: `404 Not Found` when the referenced project does not exist

Response body:

```json
{
  "error": {
    "code": "PROJECT_NOT_FOUND",
    "message": "Project not found."
  }
}
```

# Implementation Notes

* The scan execution must run in the background (e.g., using FastAPI's `BackgroundTasks`) to avoid blocking API responses.
* The repository retrieval mechanism must install `git` in the backend runtime and clone repositories to temporary directories, which must be fully cleaned up after a scan run completes or fails.
* Repository contents are not stored in PostgreSQL.
